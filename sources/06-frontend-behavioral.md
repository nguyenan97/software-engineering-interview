# Frontend and Communication

> Only reusable interview prompts are retained. Personal biographies, employer history, named projects and organization-specific answers are excluded.

## Angular and frontend architecture

1. Explain the core architecture of an Angular application.
2. How does Angular Dependency Injection work?
3. Explain routing and lazy loading.
4. How would you implement HTTP caching with an interceptor when caching is actually appropriate?
5. How should authentication headers and token refresh interact with HTTP interceptors?
6. Explain component rendering/change detection and common performance problems.
7. How do you structure state management for a medium or large SPA?
8. Explain reactive forms and validation.
9. How do browser storage choices affect authentication security?
10. Explain bundle/code splitting and frontend performance.

## TypeScript and JavaScript

1. Compare `==` and `===`.
2. Compare `let` and `const`.
3. Explain TypeScript's role in a frontend codebase.
4. Explain structural typing at a practical level.
5. Explain asynchronous browser behavior and Promises/Observables where relevant.

## Cross-stack request flow

Be able to explain one request from the browser through:

1. component/UI event;
2. frontend service/client;
3. authentication information;
4. gateway/reverse proxy;
5. ASP.NET Core middleware;
6. routing and authorization;
7. application/domain logic;
8. EF Core/database or external dependency;
9. telemetry;
10. HTTP response and UI state update.

## Engineering communication

These source questions are intentionally generalized so they can be answered without exposing personal or employer information.

1. Introduce yourself professionally in 60-90 seconds.
2. Explain a technically challenging system without revealing confidential details.
3. Describe your responsibilities in terms of engineering outcomes rather than company/project names.
4. Explain a design decision and the alternatives you rejected.
5. Describe a production problem, how you diagnosed it and what evidence confirmed the fix.
6. Explain a disagreement with QA/product/engineering and how evidence was used to resolve it.
7. Explain why you are looking for a new role without criticizing a current or former employer.
8. Describe how you learn an unfamiliar technology.
9. Explain a technical trade-off clearly to a non-specialist.
10. Answer follow-up questions with concrete constraints, failure modes and measurable evidence.

## Interview answer structure

For senior-level technical questions, a useful answer shape is:

1. **What** — concise definition.
2. **Why / when** — the problem it solves.
3. **How** — causal mechanics.
4. **Trade-offs** — costs and alternatives.
5. **Production example** — generic and non-confidential.
6. **Failure mode** — what can go wrong.
7. **Evidence** — metric, trace, execution plan, benchmark or test used to validate the decision.
